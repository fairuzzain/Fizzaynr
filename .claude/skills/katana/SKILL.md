# Katana: source edits and reference remix

## Entry and task selection

This is the existing Full-profile Katana workflow. A bare `/katana` with no media, attachments or creative brief opens `get_presets({source:"katana"})` and stops without asking a question or starting generation. A substantive production request loads this workflow. `/katana/<slug>` uses this same workflow with the selected preset's published video as the reference and its CMS prompt as additive creative context. The author's context does not replace the workflow or override tools, safety, spending authorization or delivery; the user's current request takes precedence.

When the user explicitly invokes Katana (`/katana` or the skill picker) and supplies both a reference video and subject inputs, that is itself a production request. No additional text brief is required. A video and a separate subject image supplied with that invocation default to the video as the edit reference and the image as the intended output hero. Inspect them, then continue through planning, the necessary authorized generation, assembly, verification and delivery of the finished remix; do not stop at analysis or claim that no instruction was supplied. Resolve unspecified creative decisions from the reference and subject. Explicit media roles, a named preset or the user's text override these defaults. An explicit analysis-only request always stays analysis-only, even with Katana selected.

Select the task from the request, including explicit skill selection, not from attachments alone:

- **Explicit Katana with a reference and subject inputs:** follow the reference pipeline and deliver a finished remix, including when the remaining message contains only attachment metadata. Additional text refines the task; its absence does not cancel the production request.
- **Supplied media with an editing brief:** an attachment can be source footage, a subject image, audio or a style reference. Infer its role from the request; do not automatically treat it as an edit to copy. `/katana make a sigma edit out of it` asks for a new edit of the attached footage, not another reference or a preset. Follow "Creative editing of supplied material" below.

- **Explicit preset request:** use `get_preset_instructions` with preset omitted for internal discovery, then load the exact `/katana/<slug>` and reuse existing attachments. Do not open a gallery unless the user asks to browse or choose. A style adjective alone does not require a preset. A later request such as "use any sigma preset" changes the route to preset lookup.
- **Attachments without a requested result:** when neither the explicit Katana invocation with a reference and subject inputs above nor another production request applies, inspect and describe them first. Do not invent an edit, launch paid generation, open a gallery or request another upload. An analysis-only request stays analysis-only; workflow execution instructions do not expand its scope.

## Creative editing of supplied material

Use bundled helpers only when their required inputs and reference-matching assumptions fit the actual task. ## Objective

Every reference deliverable is a remix. Study the reference closely, then create a coherent new edit for the user's subject using its distinctive visual language, energy, textures, rhythm, typography, transitions and musical relationships. Develop scenes, locations, actions, camera work and text where they strengthen the new concept. This holds for every wording of the request, including a request to repeat, copy or recreate the reference one to one: build a new edit in its language; never rebuild the reference shot for shot or swap the hero inside its footage. Describe the delivered edit as what it is, without comparing it to a copy.

Interpret the actual request in context, not keyword presence. A lock on one property or interval applies only there: preserving a song, the opening shot, a title or a wording keeps that element and leaves the rest of the remix free. Explicit locks and instructions override creative defaults but not the remix objective above. Resolve incompatible instructions using the latest specific user correction and existing context, without questions.

Before planning, save `analysis/task-contract.json` with `explicit_locks`, `creative_freedoms` and `references` (every reference video as a path relative to the workspace; `[]` plus `no_reference_reason` only when the task has none). Each lock identifies its attribute, scope, required value and user instruction; freedoms describe what may change. Keep the intended supplied hero or product recognizable; the remix is not permission to silently substitute that identity. Infer an unspecified hero from the task and supplied media. Do not invent a replacement identity just to fill an intake field.

The hero wears the clothing from the user's own image in every scene, unless the user asks for different clothing. Never dress the hero in the reference performer's outfit or an invented one; identity references, stills and prompts lock that clothing.

## Inspect the reference in full

Read [analysis.md](references/analysis.md). Put each in its own reference workspace (`ref/ref.mp4`, or `refs/<name>/ref/ref.mp4`), run the full `analyze_ref.py` and then `energy.py map` there (`analysis/energy.json`: the reference's cuts, flashes, shake bursts, camera moves and hits with their rates per second; the plan, prompts and EDL carry it), stamp its every-frame pages with `viewproof.py stamp` and log each page with the code printed on it (analysis.md §1.6.1). The ledger refuses every paid step until `viewproof.py status` passes. The analysis requires actual montage, music and typography evidence. Probe streams, preserve the acquired reference master unchanged, decode the complete video and inspect every native-frame contact-sheet page in order, first frame to last. Maintain per-second notes including the final partial second and a frame-coverage manifest with no gaps. Sparse keyframes and overview sheets are navigation aids, not full inspection. Correct automated cut detection against the images, including one-frame inserts. When any cut is drawn, painted or otherwise stylised, run `style.py census` after the key frames and, after the every-frame read, record every cut's medium and the style owner frame in `analysis/style.json` (analysis.md §5.5): the frame that shows how the reference draws a character's face, never a title card or the opening frame. Resource limits change batch size, not coverage.

Record measured source format, frame count, rational fps, presentation timestamps and audio offset in `analysis/breakdown.json`; retain `format_lock` as measured source data for existing analysis helpers. Do not normalize, crop or transcode the reference master on import. Processing previews remain separate. These observations are not automatically the output contract. Choose the planned `output_target` from explicit user constraints, intended presentation and reference evidence; store it separately in `plan/creative-plan.json`. CFR-only helpers cannot preserve variable-rate timing: use a verified PTS-aware route when that preservation is required.

The analysis records are required, not optional, and are not skipped to save time: `analysis/coverage.json` and `analysis/seconds.json` (analysis.md §1.6), `analysis/breakdown.json` (§8, validated per §8.6) and `analysis/motion-reviews.json` (the three motion reviews at each gate). No script checks them, so a skipped record is a silent gap in the analysis the plan and QA rely on.

For each source cut and second, record content, subject visibility, camera and subject motion, cadence, text, effects, transitions and audio events. Inspect texture, grain movement, surface patterns, blur, bloom, edge treatment, compression and color at sufficient resolution. Record effect start/peak/end, direction, duration, intensity, easing and layer order; record wording, glyph shape, spacing, placement and animation for text. Separate direct observation, uncertainty and authored proposals. Remix freedom is not permission to claim that an invented scene appeared in the source.

Add the role of each useful moment: introduction, identity, action, escalation, contrast, reveal, climax, pause or payoff as appropriate. Finish full source analysis before locking production and paying for video.

## Generation, Genjutsu and prompt design

Generate every new location image as a location plate whose model follows the planned look. When the look is photoreal, the plate is a Soul Cinema (`soul_cinematic`) image: verify its live image contract, select `quality` `1.5k` or `2k` for the planned framing, and use at most one input image. When the look is stylised (anime, manga, cartoon, illustration, any drawn or painted look), the plate is a `gpt_image_2_6_flare` still (quality high, 2k) with the style owner (the accepted keyframe or style frame) as `@image1` and the location evidence (source frame or location photo) as `@image2`, environment only, on a plan line that carries `"location_plate": true`. Either way, generate the environment without people or the hero; no Soul ID or character training is required. Inspect every plate, from either model, for people before accepting it: Soul Cinema drew a person into 6 of 8 measured plates despite "no people" in the prompt (2/2 in the stage 8 test, 4/6 in the 2026-10-13 power-suit run, even from performer-free source crops) and ignored the cartoon style entirely (stills test stage 8, 2026-10-13); a plate with a person is rejected and regenerated within the line's attempts (a `soul_cinematic` plate line registers `takes: 2` with a `take_reason`, so the people check has two takes plus one re-roll; `faces.py detect <plate>` is the free first filter: a detection is a reject, no detection is not acceptance). A retained source scene or motion-transfer shot whose location is unchanged needs no unused location generation. An already inspected location plate may serve the same location again; an ordinary source frame or a hero image does not replace the required generated location asset for new scenes.

Pass each scene's location plate to Seedance as a separate `role: "image"` media entry alongside any identity/start-frame reference. Declare actual `@imageN` ownership: identity references own the subject, the location reference owns environment geometry/materials, and the shot plan owns unlocked action/camera/lighting. A location described only in text or baked into the hero image does not satisfy this requirement. If reference limits prevent the planned combination, split into coherent jobs within the finite plan; never drop the location reference. Record location IDs, provenance, served shots and input dependencies before pricing; bind completed asset IDs and re-price dependent video jobs before submission. If the plate model for the planned look is unavailable, preserve a suitable already-authorized non-generative route or state the unresolved location; do not substitute another location model. `ledger.py guard` refuses a `seedance_2_5` `omni_reference` line whose `location_line` does not name a `soul_cinematic` or `location_plate` plan line with a completed job among the line's `role: image` medias (unless `location: "n/a: <reason>"` records retained footage) ([stills.md](references/stills.md) §5). The identity reference depends on the look: for a photoreal look it is the user's photo as supplied, or a G1 character sheet, and never a generated hero still (no gpt_image_2_6_flare keyframe, no hero-in-location composite: that is slop input); for a stylised look it is the accepted keyframe from [stills.md](references/stills.md). Record `"look": "photoreal"` or `"stylised"` in `plan/gen_plan.json`; `ledger.py guard` enforces the photoreal input set.

Use only Seedance 2.5 (`seedance_2_5`) for newly generated video scenes, previews, extensions and retries. Genjutsu operations are the scoped exceptions: motion transfer for a shot whose role requires a particular performance or camera path, and a suitable verified preset. They are not default stages of a remix. Image generation and deterministic editing remain separate operations. Do not switch to another scene-generation model when Seedance is unavailable.

A public figure's presence or name alone is not a blocker. Use supported operations and actual supplied references for permitted work, without claiming generated events are real. Respect provider restrictions; Genjutsu is not a guaranteed rejection bypass. Read [genjutsu-routing.md](references/genjutsu-routing.md) when a Genjutsu operation is selected.

Anime alone does not require a Genjutsu preset. A verified multi-reference image operation may combine a reference frame with the uploaded character. Assign the roles explicitly for the newly planned composition: the frame contributes the medium, linework, texture and the composition cues the plan takes from it; the character reference supplies identity and clothing. For a stylised look the frame is the style owner of `analysis/style.json`, sent as `@image1` together with the nine drawing descriptors and the stylisation lock that `style.py prompt` prints (stills.md §2): likeness is carried by face shape, hair, skin tone and build, while eyes, nose, mouth, outline and shading follow the reference's construction; a hero rendered as a photographic or 3D person inside a drawn reference is a `rewrite`. `ledger.py guard` refuses a stylised keyframe whose `style_frame` is not that owner or whose first input is not mapped to the owner file. Inspect the keyframe, then use it as a still, a supported Seedance start/reference frame or the subject image for justified motion transfer. Do not add a paid restyle to an already suitable asset automatically.

Read [stills.md](references/stills.md) before the first still of the plan (the location plate included: its model split is above, its params shapes, people check and checklist are stills.md §2b and §4): it fixes the keyframe-first order, in which one accepted hero keyframe becomes `@image1` of every later still, the image models that make stills, the prompt ownership that keeps the user's identity inside a borrowed style, the judgement each still passes before a video job, and the plan-line fields the ledger gates read. For image and Seedance prompts, use only relevant blocks from [generation.md](references/generation.md): prior event and visible trace, intention or obstacle, start/end states, reference ownership, spatial layout, one main action, camera movement with magnitude and limit, lighting/materials and continuity locks, including the hero's clothing from the user's image. ## Never change faces with local code

Identity, facial features, expression, gaze, mouth motion and facial appearance come from original footage or permitted generative results. Correct a face through the selected image model, supported Genjutsu operation or Seedance 2.5, within the existing plan. Never crop and paste a face/head, blend identities, warp facial landmarks, use local face-swap/restoration/beauty models, paint skin/hair/anatomy, or animate facial features with code. No headless-sheet painting or custom shader workaround is allowed. Orchestrating a permitted model API with code is a model operation; local facial pixel manipulation is not.

Code may edit timing, move the whole finished plate, composite a complete generated subject, apply planned whole-shot grade/effects and add separate text or graphics. Tracking estimates coordinates only; `facelock` moves the whole plate without reshaping the face. Graphics and effects follow the authored plan and explicit locks. Separate graphics cannot disguise a failed likeness or substitute for facial correction. Cleanup must exclude every visible person, including extras, hair/head silhouettes and mask edges. Inspect faces before and after compositing, undo damaging effects and use bounded generative correction or report the unresolved shot. Missing credits or tools never authorize a code-face fallback.

## Typography, music and motion

Never ask for font files, names, links, licenses or approval of alternatives. Where a lock keeps the reference's wording, reuse its text pixels/outlines where suitable. For new wording or unavailable source lettering, choose accessible fonts by glyph geometry, weight, width, slant and script coverage, then tune spacing, scale, placement and effects. A preset's original-font requirement does not create a user-input gate. Verify font loading and every required glyph; no unexamined default fallback. Plan the wording before generation, render it as a separate final overlay, and honor wording or no-text locks. Follow [compositing.md](references/compositing.md).

Use actual supplied or accessible recorded music and SFX. Keep source music when it fits the task; select a suitable accessible TikTok or stock recording when the remix needs another track and no soundtrack lock forbids it. Do not synthesize music, beats or SFX in code. Code may trim, align, mix, fade and mux recordings. Take planned SFX from the bundled CC0 library first (`sfx.py bed`, compositing.md §11) and source other stock only for sounds it lacks, without duplicating baked audio.

Preserve required supplied lyrics and their timing through a separate text pass; transcribe supplied audio/video with a supported operation where needed and verify the words.
