# Craft Parallax Video (paper cut + 13 other diorama styles)

Reply in the user's language (default: informal Bahasa Melayu / rojak when they write in Malay), concise. Work autonomously: ask once, then run end to end.
Only use this skill when they explicitly ask for a parallax / diorama / one of the styles below.
The video is always composed here with the scripts in `scripts/`; never use a cloud service to generate the video itself.

Every scene = 3 layers: **bg** (no people) + **char** cut-out(s) + **fg** border. `scripts/render.py` does camera moves,
depth of field, idle animation, particles, texture, style transitions and captions; `mix.py` adds music, SFX and VO.
All code is ready in `scripts/` (run it from the working dir, don't rewrite it). Fonts are bundled in `fonts/`.
`S=<this skill dir>/scripts` below.

## Setup: Python (check once per chat, esp. Claude Code on a Windows PC)
Scripts here need Python 3 + numpy, pillow, scipy and ffmpeg. Check: `python --version` (or `py --version`) and `python -c "import numpy, PIL, scipy"`.
- **Windows:** `python3` usually doesn't exist and plain `python` may be a Microsoft Store stub → use `python` (or `py`) in every command below where it says `python3`. Missing → install it yourself, don't skip steps:
  ```powershell

No `--break-system-packages` on Windows. ffmpeg missing → `winget install -e --id Gyan.FFmpeg --scope user`. If winget fails, ask them to install Python from python.org (tick "Add python.exe to PATH") and wait.
- Linux/Mac sandbox: `pip install numpy pillow scipy --break-system-packages -q` if an import fails.

## 2. Plan scenes (draft.json, no timing yet)
For each scene: bg, fg, chars (`file`, `x`, `h`, optional `idle`), caption (≤ 30 chars), optional `cam`, `particles`.
Vary the camera so scenes don't feel the same (default rotation push → pan → tilt → pull → pan → reveal):
`push` (move in, intimate), `pull` (move out, reveal context), `pan` (sideways travel), `tilt` (up, hope/aspiration), `reveal` (big opening/ending), `still`.
Idle (character): `breathe`, `sway`, `bounce` (happy/excited), `none`; default = breathe + light sway.
Particles: `dust` (default warm air), `confetti` (win/celebration scene), `sparkle` (magic/idea), `none`.
Timing is NOT written by hand: `plan_scenes.py` derives it from the VO (§5). Template in `references/prompts.md`.

## 4. Cut-outs
```
python3 $S/keyout.py c1.png --key green   --split x --prefix p     # -> p1_cut.png p2_cut.png p3_cut.png
python3 $S/keyout.py c2.png --key green   --split x --prefix p --start 4   # -> p4..p6
python3 $S/keyout.py f1.png --key magenta --split y --prefix f1_   # -> f1_1_cut.png f1_2_cut.png
```
Auto-split finds the empty gaps; if poses touch, pass `--cuts 0,850,1700,2560` (look at the image first).
Keys by hue (handles muted green/magenta + soft floor shadows), keeps arm/leg gaps open, despills edges, drops stray patches.
**Always open `<name>_contact.png`** (cut-outs on a contrasting checker) and fix halos, leftover shadow patches, missing grey/silver props or holes before rendering.

## 5. VO → timing
- Script ≈ 2.3 words/s minus pauses (15 s ≈ 30–35 words, 30 s ≈ 55–65 words), one line per scene, saved to `script.txt`.
- Show the spoken text in ONE code block with a short scene breakdown, then generate one file.
- English VO: `bun "${NEXABOT_TS:-$ROOT/vendor/Motion_as_kit/nexabot/nexabot.ts}" tts "<text>" --voice Fenrir --out vo.wav` (0.15 credit per request, no tone option).
- Malay VO: `python "${MOTION_KIT:-$ROOT/vendor/Motion_as_kit}/gemini_tts.py" -f script.txt -v Fenrir -i "<tone>" -o vo.wav` (Nexabot TTS rejects Malay; the free tier allows 10 requests a day per model, so send the whole script in one request).
- Never ElevenLabs. Voice names and the project voice lock follow the global rules.
- Convert it with `ffmpeg -i vo.wav vo.mp3` for the steps below. If the user supplies their own VO, use that file.
- Voice-memo filenames (e.g. a street name) are just the recording; treat it as the VO they promised.
```
python3 $S/split_vo.py vo.mp3 script.txt line > vo.json     # cuts line1.wav.., checks loudness of every clip
python3 $S/plan_scenes.py draft.json vo.json                # -> scenes.json + vo_args.txt (timing from the VO)
python3 $S/plan_scenes.py draft.json none                   # no VO: even split over "target"
```
`split_vo` prints `CHECK …` for a clip that is quiet (< −30 dB) or short (< 1.2 s): then find the pauses yourself (RMS in 20 ms frames, threshold max−25 dB, pauses ≥ 0.12 s) and cut by hand with input seek: `ffmpeg -ss S-0.05 -t D+0.12 -i vo.mp3 -af "afade=t=in:d=0.03,afade=t=out:st=D-0.06:d=0.06" lineK.wav`.
`plan_scenes` puts each VO line 0.4 s into its scene, ends the scene ≥ 0.5 s after the line, overlaps scenes 0.6 s (the transition), and starts the tagline on the CTA word (`"cta_word"` in draft.json). If the VO runs long it tightens the gaps, then prints a WARNING with the atempo needed (use only if ≤ 1.12) or the new length: tell them.
Optional content check: transcribe with the `whisper` skill (language Malay).

## 8. Render + music + SFX + mix
```
python3 $S/render.py scenes.json                 # -> video.mp4 + events.json (transition / caption / tagline times); multi-core
python3 $S/music.py <DUR> music.wav <mood>       # ceria | hopeful | sedih | epic | chill | kids  (or use their own file)
python3 $S/mix.py video.mp4 music.wav out.mp4 <DUR> --sfx events.json $(cat vo_args.txt)
```
Moods: pick from the story, and not the previous video's mood if another fits. Their own mp3 goes straight into mix.py (looped if short).
SFX are automatic from events.json: paper rustle on torn/page transitions, whoosh on slide/crossfade, pop on pop/drop/slide captions, chime on the tagline. Leave out `--sfx` if they want it clean. Without VO, mix.py raises the music level itself.
Optional overrides at the top of scenes.json: `"transition"` (crossfade | slide | torn | page; also per scene), `"texture"` (paper | fabric | none), `"particles"`, `"dof"` (bg blur, 0 = sharp), `"stopmo"` (true/false).
**Check before delivering:** 5–6 frames on a contact sheet (captions inside the frame and all one look, tagline not over faces, fg visible but not hiding the character, no halos, no weird hands) and the audio: `ffmpeg -ss <t> -t 5 -i out.mp4 -af volumedetect -f null -` for each 5 s window (mean > −30 dB where there is VO). Then run the QA gates: `python3 $S/look.py out.mp4 --expect-duration <s> --audio --sheet qa.jpg` → every gate PASS: decodes, right size/length, audio present, no frozen run > 0.4 s mid-video (deliberate pauses: `--allow-still <t>`), end hold ≤ 1.5 s. FAIL = fix and re-render, don't deliver. Look at `qa.jpg` (frames from the real MP4). Quote the numbers in one line of the summary. Never deliver without these checks.

## Gotchas
- Text inside generated images is unreliable: captions are always added by the renderer.
- Studio/brand names in prompts: remove them and describe the look instead.
- Pale objects vanish or get holes when keyed: ask for saturated colours. Grey/silver props (laptops) reflect the key: the saturation rule in keyout.py keeps them, check the contact sheet anyway.
- Props from the sheet (a cliff wall next to a climbing pose) or a second figure: crop with `--cuts` or erase before rendering.
- 3d style: characters drift between generations; reuse the same description and keep all poses on one sheet.
- Codex jobs that run past ~5 min usually still finish; keep polling instead of starting a duplicate.
- Full render ≈ 1 min per 30 s at 720p on 2 cores (faster with more cores); 1080p ≈ 2x.
