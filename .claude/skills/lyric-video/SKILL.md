# Lyric Video

Turns **one song (30-ish seconds of it) into a finished 1080x1920 / 60 fps kinetic-typography lyric video**: every word pops on the beat, every lyric line gets its own typographic grammar, one warped fisheye grid binds all shots, and **the camera is always travelling**. It is drawn by code (WebGL in headless Chrome) and built by agents: builders, independent critics who LOOK at rendered frames, revisers. An optional **art department** (step 4B) adds AI pictures and video clips via Nexabot (Google Veo / Gemini backend, Seedance 2.5) to the type.

**Where things live.** `<skill-dir>` = the folder that contains this SKILL.md. `<kit>` = `<skill-dir>/kit`, or the folder in `$LYRICVIDEO_HOME` when that variable points to a valid kit: it holds the engine, tools, templates, workflow scripts and `node_modules`. A new video is its own project folder: `<project>` = `$LYRICVIDEO_PROJECTS/lv_<slug>` when that variable is set, else `~/lyric-videos/lv_<slug>`, or the folder you passed as `--out`; `tools/new_video.mjs` creates it with its own COPY of the engine, tools, docs and workflow scripts. Every `node tools/...` / `python3 audio/...` command runs inside `<project>`. The full runbook is `<project>/PIPELINE.md` (every flag); this skill is the short, ordered version plus the gates.

**Words used here.** *Director* = you, the main session (talks to the user, runs the gates). *Scene* = one timeline segment with its own lyric line(s) and treatment, one file `scenes/<id>.js`. *Flight* / *whip* = the camera travel between two scenes. *Asset* = a generated picture or clip in `assets/manifest.json`; *device* = how it is used (FILL, WORLD, KEYED, STICKER, clip). *`Reel`* = the engine's global object.

## Install and first run (once per machine)
1. **Put the skill in place** (Claude Code on a Mac: local shell, Chrome, ffmpeg): `mkdir -p ~/.claude/skills && cp -R lyric-video-openart ~/.claude/skills/` run in the folder that holds `lyric-video-openart` (the folder that directly contains this SKILL.md). A `lyric-video-openart.skill` file is that folder as a zip (`unzip` it there); sandboxed chat apps are not supported (no macOS Chrome or GPU).
2. **Install the kit's dependencies, one time** (internet, about 50 MB, 1-2 minutes): `bash <skill-dir>/scripts/setup.sh --install` runs `npm ci` inside `<skill-dir>/kit` only (puppeteer-core plus bundled open-source fonts). Say what it does and get the user's OK first: it downloads packages.
3. **Prove the machine works, without any music**: `bash <skill-dir>/scripts/setup.sh --smoke` (synthetic click track, throwaway project, one tiny frame, all deleted) must end with `doctor: all good - ready to make a lyric video` or, with warnings (normal without whisper), `doctor: ready to make a lyric video (N warning(s) above - read them)`; a `[FAIL]` line is the failure: fix it.
4. **Only for the art department (optional):** art department generation routes through the user's **Nexabot** client (`bun "${NEXABOT_TS:-$ROOT/vendor/Motion_as_kit/nexabot/nexabot.ts}"`: `img`/`gpt-image` for pictures, `sfv`/`nexadance` for clips); never require the OpenArt MCP. The host owns the sign-in: never ask for, accept or type credentials; `openart_account_get` proves the session.

## THE HARD GATES (a human or a measurement must say yes; never skip, never decide for the user)
* **GATE 1 - LYRICS VERIFIED BY THE USER (step 2).** The user pastes the lyrics; whisper only cross-checks (it mis-hears sung lyrics and runs early). Nothing is built on unverified text; `build_timing.py` refuses a file that is not `"verified": true` (never use `--allow-draft` to get around it).
* **GATE 2 - BRIEF + TREATMENT LIST APPROVED BY THE USER (step 4)**, before the expensive scene round. An explicit yes, recorded in `BRIEF.md`.
* **GATE 2B - ART PLAN APPROVED BY THE USER (step 4B, only when the art department is used).** Before ANY picture or clip is generated or downloaded the user approves provider, models (GPT Image 2 pictures, Seedance 2.0 Mini clips; a weaker one only for a named item the user asked for), numbers of images and clips, credit estimate and ceiling, the pilot clip and the download; recorded as ART APPROVAL RECORD in `BRIEF.md` and `plan-approve --yes`. No credits are spent without it.
* **GATE 3 - CAMERA-TRAVEL GATE on the first assembled draft (step 6)**: measured numbers (no static stretch; landing spread on the INK boxes, with the recorded exception for wide words), not impressions; a video that does not travel goes back to the scenes.
* **GATE 4 - THE FREEZE (step 7 -> 7B).** A fresh composite critic says ship with score >= 8.5, or its only blocker/major items are rule shortfalls (arithmetic, not craft) that you fixed in a one-track micro-round and re-measured by script; record the numbers in `notes/FREEZE.md`. After the freeze nothing changes until final QA (8B) has spoken.
* **Opt-in:** the Workflow tool needs the user's explicit OK (below).

## Step details (every flag and failure mode is in `<project>/PIPELINE.md`, step by step)

**Step 0 - scaffold.** `new_video.sh` checks the machine, runs `tools/new_video.mjs` (copies the kit, cuts and analyses the song, runs whisper when available (2-5 min: background), writes DRAFT transcript and timing) and renders one tiny frame as a boot test. A session limited to another folder adds `--out <dir>` (= `<project>`). Whisper is optional and big (1.5 GB): get a yes before `--allow-download`. Never `--force` a project that has work.

**Step 1 - song prep.** Judge `top tempo candidates` / `tempo sanity`; half/double-time or drift: re-run with `--bpm <value>`, which locks the tempo (probe 60-90 s around the window once into a scratch folder, never the default `audio`: PIPELINE.md Step 1). `downbeat guess` is only a guess (confidence 0.25 = no information): decide it from the kick entry, line starts/ends and the backbeat on spectrograms, then set `"downbeat": N` in `lines.json`.

**Step 2 - lyrics gate.** The USER PASTES the lyrics (line breaks = sung phrases, every repeat written out); they live only in `audio/lines.json` (schema: PIPELINE.md Step 2). Answer with line ids, word counts and syllable counts: never echo the text into the chat, notes, prompts, args or reports. The whisper draft (`audio/lyrics.draft.txt`) is only a cross-check, reported by id. Take corrections **as written by the user**. **Line ids and word counts are what every scene binds to** (`Reel.audio.word('L3', 2)`): settle them now; record who confirmed and when in `BRIEF.md` section 1.

**Step 3 - timing.** `python3 audio/build_timing.py` snaps every word to the 16th-note grid (+-0.11 s) and writes `audio/timing.json` (the single source of truth for timing AND text). `node tools/specmark.mjs` writes `previews/spec_<t0>-<t1>.png`: open EVERY one with the Read tool; the solid bar (snapped `ts`) must sit where the syllable's energy visibly starts. Fix with `audio/timing_overrides.json` = `{ "L1.2": 1.052 }` (line id.word index, seconds), rebuild, re-look. **Vocoded, ducked or chant tracks, and any run without whisper:** skip snapping (aligner agents: `references/agent-prompts.md` section 6).

**Step 4 - brief and treatment list.** Delete the two "HOW THIS FILE WORKS / TEMPLATE NOTES" blocks first (they contain `<<` themselves), then fill every `<<...>>` in `BRIEF.md` and `design/SCENES.md`; keep sections 0, 3, 4, 6, 7. Decide the arc, the palette, **one treatment per scene from the menu** (`references/treatment-menu.md`), a camera idea per scene, the landmark beats and flights, and turn the placeholder plan into the real `scenes/manifest.js` (ids like `s1_pop` = file `scenes/<id>.js`). Give every word a size tier and a target position (`node tools/landing.mjs plan notes/landing_targets.txt`), write the declared flash frames and gate exceptions into BRIEF section 6, run ONE fresh critic over the brief (`references/agent-prompts.md` section 7), then **show the user the one-page storyboard** (`references/treatment-menu.md` section 4), wait for an explicit yes, `cp -R scenes scenes_bak_0`. A new palette: new values for the 10 `Reel.C` slots in the PROJECT's `engine/core.js`.

**Step 4B - art department (optional).** After GATE 2, before step 5; rulebook `references/art-department.md`, steps PIPELINE.md Step 4B, runbook `references/providers/nexabot.md` (or `references/providers/openart.md`). **Plan:** `generic_art.js` mode `plan` (`clips: true` for clips) writes `assets/plan.json` from the APPROVED storyboard; once any scene has a clip, list a moving plate or fill for EVERY scene in `plan.clips` before GATE 2B (people only if the user said yes); `node tools/assets.mjs plan-check` and `plan-cost` must be clean. **GATE 2B:** show provider (Nexabot), models (Gemini Imagen, Veo / Seedance 2.5), image and clip counts, the credit quote with its config, the ceiling, the pilot clip, the download permission, the people answer and the rights sentence; ask the credit choice (pictures high, clips 480p by default; 720p doubles the price) and quote any weaker tier in `plan.modelApproved`; after a yes `node tools/assets.mjs plan-approve --yes --ceiling <C>` (pictures + clips, cumulative) and an ART APPROVAL RECORD in `BRIEF.md`. **Generate** (never a weaker model, tier or provider silently; in sub-agents, never from the main session of a host that shows OpenArt cards): pictures with mode `generate-nexabot` (or `generate-openart`); clips with `generate-nexabot-clips` (or `generate-openart-clips`): ONE pilot clip first (`pilot: true`, checked end to end, `notes/clips_pilot.json`), then the batch (`approved: true`, `maxCredits`, `spentSoFar`; never resubmit a job, collect it). Then mode `review`, `import-dir`, `prep all`; clips: look at each, `clip-prep --from-log`, `check` (exit 0); an "ART:" sentence per scene `extra`.

**Step 6 - assemble, camera gate, draft.** Run `node tools/preview.mjs --global --range 0:<dur>:0.5 --cols 8 --cw 130 --scale 0.5 --S 8` and `node tools/analyze.mjs --global --from 0 --to <dur> --no-image --flights` (`references/qa-checklists.md` section 1): `analyze` must print `no camera-static stretches` and `no camera discontinuities`; the contact sheet must show real travel and parallax. Measure the landing spread on INK boxes (`node tools/landing.mjs measure`, save `notes/landing_r1.txt`) against the floors of that section (std-dev >= 150 px x and >= 250 px y per 10 consecutive words); a recorded exception overrides. Render a low-res draft (`node tools/render.mjs --workers 2 --scale 0.25 --S 4 --fmt jpg --frames out/frames_v1_ref --mp4 out/wip_draft_v1_270p.mp4`), send it to the user and ask for reactions BEFORE the composite review.

**Step 6B - composite review (once, before polish round 1).** Only a review of the whole sees seams, people coverage and render risks. Run `generic_composite_review.js` (4 lenses + a synthesiser, ~45 min) with recorded facts in `notes`, never your conclusions; save `notes/composite_review_r1.json` at once, verify the contested items yourself, write one fix list per owner.

**Step 7 - polish rounds.** Per round: `cp -R scenes notes/scenes_before_r<N>`; the previous draft's frames (`out/frames_v<N>_ref`, never written by agents) are the A/B baseline (`draftFramesDir`); ONE manifest batch edit (backup `notes/manifest.before_<stage>.js`, dated comment); one fix list per track, `notes/fix_r<N>_<owner>.json`, as `tracks[].issuesFile`; run `generic_polish.js`, save `notes/polish_r<N>.json`; then `node tools/audit.mjs --group sort,options`, `node tools/determinism.mjs --frames <f1>,<f2>,<f3> --S 16`, the camera gate and a new draft. Rounds shrink: stop at GATE 4. **A late text change:** `audio/lines.json` as the user wrote it, rebuild timing, re-check on spectrograms, adjust manifest windows/flights, run `workflows/generic_lyric_fix.js`, then the composite review.

**Step 7B - freeze.** `node tools/freeze.mjs --note '<score, exceptions, accepted minors>'` writes `notes/FREEZE.md` and `notes/scenes_frozen/`. Before it, a path-following camera (pen, cursor) must pass `node tools/camjitter.mjs` (`CAMJITTER OK` or a recorded exception, PIPELINE.md Step 7B). A fix after the freeze = micro-round, new freeze, full re-render.

**Step 8 - final render.** `df -h .` (>= 10 GB free for 30 s), then in the BACKGROUND: `(caffeinate -i node tools/render.mjs --workers 2 --maxS 192 --chroma-qp -4 > out/render_final.log 2>&1; echo RENDER EXIT $? >> out/render_final.log) &` and poll `tail -n 3 out/render_final.log` for `RENDER EXIT` (a crash never prints `wrote `). No other flag for the first delivery except `--audio-trim <dB>` (Step 8B): PNGs go to `out/frames`, the master to `out/<name>.mp4`; a later version never uses these defaults (Step 10). After a crash re-run the IDENTICAL command plus `--resume`; never splice old and new frames (a post-freeze fix: PIPELINE.md Step 7B). Exit 2 / `SCENE ERRORS:` = fix, don't ship. Then `node tools/verify_video.mjs` and **look at the video** (`references/qa-checklists.md` section 8). **Quick test render** (3 s): `node tools/render.mjs --from 0 --to 179 --scale 0.25 --frames out/frames_test --mp4 out/test_3s.mp4`, verified as in PIPELINE.md Step 8.

**Step 8B - final QA.** `generic_final_qa.js` (read-only lenses on the lossless PNG frames and the mp4: sequence, encode, eyes_a, eyes_b, soft; a fresh skeptic re-checks every blocker/major); pass `flashFrames`, `draftFramesDir`, `notes`. Save `notes/final_qa.json`: `ship: true`, or work through `punchList` (6 agents, 2.3 M tokens, 78 min on the third production). The share mp4 comes after it, from `previews/qa_encode/recommended.sh` (PIPELINE.md Step 8B). A true peak above -1 dBTP: trim the song by the measured peak (master `--audio-trim <dB>`, 4K `AUDIO_TRIM=<dB>dB`, share `-af volume`; PIPELINE.md Step 8).

**Step 8C - native 4K (optional).** First the 12-frame sample test of PIPELINE.md Step 8C (4 min), then `bash tools/render4k_chunked.sh` in the BACKGROUND (log `out/render_4k.log`; ~45 min wall for 26 s under load, >= 15 GB free), `node tools/verify_video.mjs out/<name>_4k.mp4 --scale 2` and `python3 tools/compare_encodes.py out/<name>_4k.mp4 out/<name>.mp4` (COMPARE OK). It sharpens type and 3D edges, not AI plates; above ~250 Mbit/s keep it as the archive and deliver a crf 19 transcode.

**Step 8D - QA of the files of a (re)delivered version.** `generic_files_qa.js` (read-only; 8B stays the first delivery) on the version's lossless frames and mp4s: lenses by what changed (`numbers`, `fourk`, `half1`, `half2`; `peak`, `restore`, `seams` for a changed range), each started only when its inputs are final; after a fix re-run only the lenses it invalidated, under a new tag (`v3b`). Save `notes/files_qa_<version>.json`: `ship: true`, else the punch list is done (PIPELINE.md Step 8D).

**Step 9 - delivery.** Hand over: the master mp4, the share mp4, the project path, a cover still (the final render's own `out/frames/f_<NNNN>.png`, copied BEFORE deleting frames) and a 5-line summary (length, BPM, scenes, critic findings and how they were resolved, anything unverified). **Say in plain words which file is for what:** upload the master to Instagram, TikTok or YouTube, the share file is for messaging (under 100 MB), 4K is unverified on phones and TVs; a trimmed song: by how many dB and why. **Offer separately:** captions, native 4K (8C), an upscale decision (no AI upscale of the finished master is recommended: PIPELINE.md Step 9), a different cut or palette (= a new scaffold); 16:9 / 1:1 are not supported. Repeat the rights sentence and, with pictures, the AI label and licence check; say honestly what you verified and what you did not (nobody watched it play).

**Step 9B - client note check.** After `deliverables_<tag>/` and its README exist (rules: `references/qa-checklists.md` section 12): `generic_readme_check.js` (read-only), critics `facts` (every claim against the files) and `reader` (a first-time non-engineer). Fill the QA sentence from `notes/files_qa_<version>.json` first, run both, fix, then ALWAYS one more facts-only pass (`only: ['facts']`, `final: true`). Save `notes/readme_check_<version>.json`: `ok: true`.

**Step 10 - reopened film (client rework).** A message about a delivered film is a NEW version with a tag (`v2`, `v3`): the client's words verbatim and dated in `BRIEF.md`; find which render they looked at (`tools/match_screenshot.mjs`); snapshot what they have seen; work in sandbox clones (`cp -Rc`, one owner group of scene files each); merge by an explicit whitelist in dependency order; ONE whole-film review at final scale; render into versioned paths (`out/frames_<tag>`, `--tag` for 4K, chunk reuse); pin it (`notes/FREEZE_<tag>.md`, `tools/deliver.mjs`); run 8D and 9B; send proof (before/after sheets), the changes not asked for and the open decisions with their cost. "Put it back exactly as it was" = restore the scene files byte for byte, re-render, prove it with four numbers (PIPELINE.md Step 10).

## Running the multi-agent phases (steps 4B, 5, 5B, 6B, 7, 8B, 8D and 9B)

## If something breaks (full tables: `references/troubleshooting.md`)
* no `node_modules` in the kit: `bash <skill-dir>/scripts/setup.sh --install` (one time). `[PAGE ERROR]`, `SCENE ERRORS`, a red card, exit code 2: a scene threw (a syntax error silently shows the placeholder card): read the console lines, fix the scene. `REFUSING TO BUILD`: do the lyrics gate.
* tempo x2 or x1/2, beats drift off the kicks: Step 1. Render stalled after sleep: `caffeinate -i`, re-run with `--resume`.

## Rules that keep results good
* **Never build on unverified text; never decide a gate for the user.** Quote what the user approved in `BRIEF.md`.
* **Judge by LOOKING** (Read tool on PNGs) and by numbers (`analyze.mjs`); never ship a render you have not looked at.
* **Copyright hygiene:** no lyric text in docs, notes, prompts (picture prompts included), workflow args, reports or scene code. Refer to `L3.2`; scenes read words at runtime.
* **Pictures are optional and gated:** nothing is generated, downloaded or paid for before GATE 2B; never a weaker model, tier or provider silently; no text, real people, brands or characters in a prompt; builders never generate or edit pictures; the user labels AI content and checks the licence.
* **Ownership:** agents write only their scene files, previews and notes; only you edit `scenes/manifest.js`, `BRIEF.md`, `design/`, `audio/`, `tools/`, `assets/`. Engine changes only through the additive hotfix protocol (`notes/ENGINE_PATCHES.md`); a fix every video should get goes into the kit (PIPELINE.md "Engine changes").
* **Never lower quality silently:** finals use default sampling and PNG intermediates (`--scale`, `--S`, `--fmt jpg`, `--hud`, `--no-audio`, `--from/--to` make previews). **Paid upscaling is a separate spend:** ask first (model, price, test plan).
* **A reopened film is a new version:** a tag (`v2`, `v3`), never a write into an earlier version's paths (`render.mjs` and `render4k_chunked.sh` defaults overwrite delivered files).
* **A plate or clip the client has seen and liked is a FIXED POINT:** restyle the other scenes first; change it only after a side-by-side and the client's yes; new takes get new ids; list every unrequested change with its rollback copy.
* **Critics are read-only and name their scratch with the run tag** (`previews/qa_<version>_<lens>/`), deleting only files they created, by exact name.
* **The user's own files:** delete none to make room; on an explicit list move them to the Trash (reversible), hold back paperwork (invoices, statements, contracts, tax forms, keys, design sources, archives that hold documents) and any folder named off-limits. Project outputs (frames, 4K segments, previews): ask first with sizes and the cost to regenerate; never delivered files, `deliverables_<tag>/`, snapshots, FREEZE records or `assets/_orig`.
* **Every number and every "identical" in a client note is a measurement that names what it compares with.**
* **Keep the user in the loop in plain words**: what is running, how long, what you need; show images, not code. Report honestly: open critic issues, anything unverified, every default you chose.
* **Never edit the kit for one video, and never touch another project's folder.** Never leave debug output or half-edits.
